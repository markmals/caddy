# Test oracle

Caddy is a port of [build123d](https://github.com/gumyr/build123d) 0.13.0, so build123d — not our own intuition — defines correct behaviour. The oracle turns that into executable acceptance criteria: pinned Python code computes reference values once, commits them as JSON fixtures, and the TypeScript test suite replays each fixture against Caddy.

The reference is pinned by the root `pyproject.toml`/`uv.lock`: build123d 0.13.0 on `cadquery-ocp-novtk` 8.0.1.1.0, which wraps OCCT 8.0.1. Every fixture records those versions, and the harness refuses to run against a fixture generated by anything else.

## Layout

| Path | Owner | Purpose |
| --- | --- | --- |
| `reference/build123d/oracle/` | Python | `case` registration, serializers, fixture-document assembly |
| `reference/build123d/cases/<suite>.py` | Python | One module per suite; the file stem _is_ the suite name |
| `reference/build123d/scripts/generate_fixtures.py` | Python | Runner: generate (`--check` verifies) |
| `reference/build123d/fixtures/<suite>.json` | generated | Committed acceptance criteria — never hand-edit |
| `reference/build123d/fixtures/<suite>/*.brep` | generated | BREP assets referenced by cases |
| `reference/build123d/fonts/` | checked in | Font files fixtures render with, so text cases do not depend on a machine's installed fonts (`oracle.TEST_FONT` in Python, `TEST_FONT_PATH` in TypeScript) |
| `reference/build123d/oracle.ts` | TypeScript | `oracleSuite`, `planOracleSuite`, fixture loading |
| `reference/build123d/fixtures.ts` | TypeScript | Validated accessors and comparison helpers (re-exported by `oracle.ts`) |
| `reference/build123d/tolerances.ts` | TypeScript | The tolerance constants listed below |
| `reference/build123d/tests/` | TypeScript | The harness' own tests |

## Generating and checking fixtures

```sh
pnpm oracle:generate              # regenerate every suite
pnpm oracle:check                 # fail if the committed fixtures differ
uv run python reference/build123d/scripts/generate_fixtures.py --suite geometry
```

`--check` regenerates into a temporary directory and compares the result with the committed tree, printing a unified diff of the first drifted fixture. Numbers in JSON fixtures and BREP assets compare within 1e-9 relative / 1e-12 absolute: OCCT's parallel booleans and fillets (which build123d enables) reorder floating-point sums, so regenerated values legitimately differ in their last bits; every other difference is drift. It is the guard that stops a reference change from silently rewriting the criteria Caddy is tested against: if the oracle's output moves, that has to show up as a reviewed fixture diff, not as a test that quietly starts passing.

Generation never skips anything. All of these exit non-zero with a message naming the suite, the case and the offending key: a case module that fails to import, a case that raises, a duplicate case name, a suite with no cases, a value that is not JSON-serializable (including a raw build123d object), NaN/Infinity, an integer beyond JavaScript's safe range, and a case that does not return a dict. Generation also prunes: fixtures and BREP assets whose case disappeared are deleted, so the committed tree always equals the current reference output.

Fixtures are excluded from `oxfmt` in `vite.config.ts` — the formatter would re-wrap the JSON that Python emits and make `--check` report permanent drift.

## Fixture format

```json
{
    "suite": "geometry",
    "reference": {
        "build123d": "0.13.0",
        "ocp": "8.0.1.1.0",
        "occt": "8.0.1",
        "python": "3.13.17"
    },
    "cases": { "vector/add": { "result": [5.0, 7.0, 9.0] } }
}
```

Keys are sorted and floats are written with Python's `repr`, which round-trips the exact IEEE-754 double; no value is ever rounded on the way out. `occt` comes from OCP if a future wheel exposes it, otherwise from the asserted `cadquery-ocp-novtk` 8.0.1.x -> OCCT 8.0.1 mapping in `oracle/document.py`.

## Writing cases

A case is a zero-argument function returning a JSON-safe dict. Names are lowercase `[a-z0-9._-]` segments, optionally grouped with `/`, and unique within their suite.

```python
# reference/build123d/cases/geometry.py
from build123d import Vector

from oracle import case, vec

@case("vector/add")
def vector_add() -> dict:
    return {"result": vec(Vector(1, 2, 3) + Vector(4, 5, 6))}
```

The runner puts `reference/build123d` on `sys.path`, so case modules import `oracle` as a top-level package. (`reference/build123d` itself is deliberately not a package: as `build123d` it would shadow the real library.)

Serializers available from `oracle`:

- `vec(v)` — `[x, y, z]` from a `Vector` or anything `Vector()` accepts.
- `location(l)` — `{"position", "orientation", "matrix"}`, where `matrix` is the 12-number row-major 3x4 `gp_Trsf`.
- `plane(p)` — `{"origin", "x_dir", "y_dir", "z_dir"}`.
- `shape_metrics(shape)` — `class_name`, `shape_type` (OCCT `TopAbs` name), `is_valid`, `bounding_box` (build123d's default, i.e. `optimal=True`), `bounding_box_coarse` (`optimal=False`, the `BRepBndLib` box padded by `Precision::Confusion`), `volume`, `area`, `center_of_mass` (`center(CenterOf.MASS)`, or `center()` for shapes like `Vertex` whose `center` takes no argument, else `null`), `counts` of solids/shells/faces/wires/edges/vertices, and sorted `face_geom_types`/`edge_geom_types` histograms of `GeomType` names.
- `brep(shape)` — writes `fixtures/<suite>/<case>-<n>.brep` and returns that repo-relative path.

## Writing the matching test

```ts
import { expectVectorClose, oracleSuite } from "../../../reference/build123d/oracle.ts";
import { EXACT_TOLERANCE } from "../../../reference/build123d/tolerances.ts";

oracleSuite("geometry", {
    "vector/add": expected => {
        let sum = new Vector(1, 2, 3).add(new Vector(4, 5, 6));
        expectVectorClose(expected, "result", [sum.x, sum.y, sum.z], EXACT_TOLERANCE);
    },
});
```

`oracleSuite` registers one Vitest test per fixture case and **fails** — never skips — when a fixture case has no implementation, when an implementation has no fixture case, or when the fixture header is not the pinned reference. The planning logic is the exported pure function `planOracleSuite(fixture, implementations) -> { tests, errors }`, which is what `reference/build123d/tests/plan.test.ts` uses to test those failure paths without turning the suite red.

Each implementation receives a `FixtureCase` (`{ suite, name, path, data }`). Read values through the validated accessors — `fixtureNumber`, `fixtureString`, `fixtureBoolean`, `fixtureNumbers`, `fixtureVector`, `fixtureMatrix`, `fixtureRecord`, `fixtureValue` — which throw with the suite, case and key path when a key is missing or has the wrong type, so a renamed fixture key fails loudly instead of comparing against `undefined`. `fixtureRecord` returns a nested view, so `expectVectorClose(fixtureRecord(expected, "location"), "position", actual, LINEAR_TOLERANCE)` reads and reports the full path.

The comparison helpers `expectClose`, `expectNumbersClose`, `expectVectorClose` and `expectMatrixClose` take `(expected, key, actual, tolerance)` and report case, key, both values, the delta and the tolerance on failure.

## Tolerances

All helpers apply the same rule — absolute near zero, relative for larger magnitudes:

```
|actual - expected| <= tolerance * max(1, |expected|)
```

| Constant | Value | Justification |
| --- | --- | --- |
| `EXACT_TOLERANCE` | `1e-12` | Pure float64 arithmetic replayed in TypeScript: only operation-order ULPs may differ. Use it for vector/matrix algebra that both sides compute in double precision. |
| `LINEAR_TOLERANCE` | `1e-7` | OCCT `Precision::Confusion()`, the kernel's own "same point" threshold (`Precision.hxx`). Anything the modeller itself treats as coincident. |
| `ANGULAR_TOLERANCE` | `1e-12` | OCCT `Precision::Angular()`; radians and direction cosines. |
| `ORIENTATION_TOLERANCE` | `1e-9` | Euler angles recovered from a rotation matrix lose roughly half the mantissa near gimbal poses, so degree triples cannot hold to `EXACT_TOLERANCE`. |
| `MASS_TOLERANCE` | `1e-9` | `GProp` integrates volume, area and centre of mass by Gauss quadrature over the faces; agreement is ~1e-9 relative, not `Confusion`. A unit box already returns `23.999999999999996`. |
| `APPROXIMATION_TOLERANCE` | `1e-6` | OCCT `Precision::Approximation()` (`Confusion * 10`), the slack of fitted geometry: BSpline approximations, offsets, boolean-section curves. |

Pick the loosest constant that still describes the computation under test. A comparison that needs something looser than `APPROXIMATION_TOLERANCE` is reporting a real divergence, not a tolerance problem — do not invent a wider number to make it pass.

## Expected-failure policy

Divergence from build123d is documented or fixed. It is never silenced.

- **No skipping.** `it.skip`, `describe.skip`, commented-out cases and "temporarily" deleted assertions are not acceptable ways to handle a failing comparison. The harness itself enforces the structural half of this: a fixture case with no implementation is a failing test, and so is an implementation with no fixture case.
- **No tolerance inflation.** Widening a tolerance past the table above to accommodate a failure hides a behavioural difference; fix Caddy or record the divergence.
- **Intentional divergences are asserted, not avoided.** Where Caddy deliberately differs from build123d (idiomatic naming, TypeScript-specific semantics), the implementation asserts Caddy's documented behaviour explicitly and carries a comment saying why the oracle value differs. The reviewer then sees the decision in the diff.
- **Reference bugs are pinned too.** If build123d 0.13.0 is wrong, the fixture still records what it does; the case comment states the upstream issue. Changing the fixture to our preferred answer would make the oracle useless as a port target.
- **Fixtures are generated, never edited.** Hand-editing a fixture to make a test pass is caught by `pnpm oracle:check` in CI.

## Harness tests

`vp test run reference/build123d` covers the harness itself, independently of Caddy:

- `plan.test.ts` — `planOracleSuite` reports missing implementations, extra implementations, stale reference versions and malformed documents.
- `fixtures.test.ts` — accessors throw on missing keys and wrong types; comparison failures name case, key, values and tolerance; the absolute/relative tolerance rule behaves at both ends of the scale.
- `selftest.test.ts` — runs `oracleSuite("selftest")` end to end against `cases/selftest.py`, which exercises every serializer (including the BREP asset round-trip).
- `contract.test.ts` — every committed fixture names build123d 0.13.0 and OCCT 8.0.1, every referenced BREP asset exists, and every suite except `selftest` is consumed by an `oracleSuite("<suite>"` call under `packages/*/tests/`.

## Adding a suite

1. Write `reference/build123d/cases/<suite>.py` with at least one `@case`.
2. Run `pnpm oracle:generate` and review the new `fixtures/<suite>.json`.
3. Add `oracleSuite("<suite>", { ... })` in `packages/*/tests/**/*.test.ts` with one implementation per case — `contract.test.ts` fails until the suite is consumed.
4. Run `vp test run` and commit the fixtures together with the tests.
